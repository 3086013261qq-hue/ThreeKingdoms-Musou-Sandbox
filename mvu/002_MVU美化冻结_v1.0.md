# 三国无双姬 MVU 美化冻结 v1.0

状态: FROZEN
目标: 高武三国姬 / 赤金漆器 / 玉牌 / 战旗视觉；禁止默认网页后台感。

## 1. 总体视觉基调

关键词:
- 深墨黑
- 暗朱红
- 暖金
- 玉石半透明
- 漆器边框
- 汉代纹样与战旗感
- 华丽但不拥挤

禁止:
- 白底卡片
- Bootstrap / Material 默认组件感
- 纯灰矩形面板
- 现代 SaaS 仪表盘风格
- 粗糙纯色 progress bar
- 大面积霓虹赛博风
- 用另一套完全不同的页面皮肤覆盖背景图

## 2. 主色与阵营强调色

全局底色:
- 墨黑 `#100D0C`
- 暗朱 `#6F211B`
- 赤金 `#B64A2D`
- 暖金 `#D9B96E`
- 象牙文字 `#F6EBD3`
- 次级文字 `#CDBFAD`

阵营强调色仅用于细边、印章、数值刻度，不改变全局主题:
- 曹魏: 靛青 `#405E8D`
- 蜀汉: 玉绿 `#4F7D63`
- 孙吴: 朱红 `#A94436`
- 晋: 紫墨 `#695579`
- 群雄: 铜褐 `#846240`

## 3. 字体

不得依赖外置字体文件。

标题栈:
`"Songti SC", "Noto Serif CJK SC", "Source Han Serif SC", serif`

正文/数值栈:
`system-ui, -apple-system, "PingFang SC", "Microsoft YaHei", sans-serif`

标题允许轻微字距与金色描边；正文禁止花体影响可读性。

## 4. 五阵营锁屏

### 4.1 图片

正式使用 5 张 `mvu/media/lockscreen/` 图片。
顺序固定:
1. 曹魏
2. 蜀汉
3. 孙吴
4. 晋
5. 群雄

### 4.2 构图

- 图片全屏铺满锁屏容器，`object-fit: cover`。
- 以人物面部与上半身为优先，允许按阵营设独立 `object-position` 微调。
- 顶部与底部各叠一层透明黑金渐变，中央人物区域不得被重度遮暗。
- 只保留极少文字: `三国无双姬`、当前阵营名、`n / 5`。
- 标题不得盖脸。

### 4.3 导航

- 左右箭头为圆形半透明黑金按钮。
- 视觉直径 30～34px，但真实触控框至少 44×44px。
- 页码置底部中央，使用小型玉牌/漆牌样式。
- 中央点击进入 MVU；按钮点击不得穿透触发进入。
- 支持 swipe；动画 220～280ms，使用 transform，不做大面积滤镜动画。
- 禁止自动轮播。

## 5. MVU 主背景

正式背景使用 `mvu/media/background/` 中咩姬×多娜彩蛋图。

背景特点: 彩蛋人物位于上方，中央天空区域留白，适合承载 UI。

固定处理:
- `background-size: cover`
- 优先 `background-position: center top`
- 页面最底层再叠 `linear-gradient`，从顶部轻暗、中央透明、底部加深。
- 不裁切到完全看不见咩姬或多娜。
- UI 主内容优先落在画面中央留白区与下半区。

## 6. MVU 顶栏

- 顶部中央标题: `三国无双姬`
- 次标题随页面: `阵营亲和` / `名姬风华录`
- 右上角可放极小 `X / 89` 收藏进度，但不得堆当前时间、地点等咩咩已有信息。
- 顶栏使用窄幅半透明漆黑底 + 1px 暖金线，不做厚重导航条。

## 7. Page 1「阵营亲和」视觉

采用一块中央「五方玉榜」，不是五张巨大独立卡片。

每个阵营一行，结构:
`阵营印章 | 阵营名 | 阶段词 | 数值`
下方附一条双向亲和刻度。

刻度规则:
- 中央为 0。
- 正值从中央向右生长。
- 负值从中央向左生长。
- 轨道细而精致，使用暗金凹槽；填充使用对应阵营强调色并叠少量金色高光。
- 禁止使用浏览器默认 `<progress>` 外观。

数值显示:
- 正数显式带 `+`，如 `+38`。
- 0 显示 `0`。
- 负数显示 `-23`。
- 数字使用等宽数字特性 `font-variant-numeric: tabular-nums`。

行面板:
- 背景 `rgba(18, 13, 11, 0.58)` 左右。
- 1px 暖金透明边。
- 圆角 12～16px。
- 可使用小范围 `backdrop-filter: blur(6px)`，不支持时直接透明底降级。

本回合 delta 默认不常驻占位；若非 0，可在数值旁出现一次轻量 `+3` / `-5` 小徽记，下一次刷新自然消失。

## 8. Page 2「名姬风华录」视觉

### 8.1 总体

- 页面顶部: `名姬风华录` + `已录 X / 89`。
- 下面一行小型阵营筛选玉签。
- 主体使用紧凑 3 列名片网格；超窄屏可退化为 2 列。
- 名片不需要点击，不加详情弹窗。

### 8.2 已点亮名片

只显示两行:
- 第一行: 角色姓名
- 第二行: `♥ 67`（咩咩原生好感度）

视觉:
- 暖黑半透明玉牌。
- 顶部极细阵营色线。
- 姓名象牙白/淡金。
- 爱心与好感数字使用暖朱红，不做粉色恋爱手游风。
- 点亮首次出现时允许 180～240ms 金线扫过/淡入一次，禁止持续闪烁。

### 8.3 未点亮名片

- 姓名固定 `???`。
- 第二行 `未邂逅`。
- 低对比度磨砂黑玉样式。
- 不显示真实姓名首字、武器、阵营提示、剪影等可剧透信息。

## 9. 底部页签

MVU 只有两个页签:
- `阵营`
- `风华`

要求:
- 固定在 MVU 内部底部，不遮聊天输入区。
- 每个按钮触控高度至少 44px。
- 当前页用细金线 + 微光印章标记，不用大块高饱和背景。
- 支持左右 swipe 切换两页；按钮与 swipe 状态必须同步。

## 10. 动效

允许:
- 页面切换 220～280ms 淡入 + 轻位移。
- 名片首次点亮一次性金线/淡光。
- 阵营数值变化时 200ms 数字过渡或刻度条过渡。

禁止:
- 无限呼吸光
- 无限粒子雨
- 大面积背景缩放循环
- 持续旋转纹章
- Canvas 常驻粒子

必须支持 `prefers-reduced-motion`，开启后取消非必要动效。

## 11. Android / SillyTavern 性能硬规则

- 不将 PNG 转 Base64 塞入卡本体。
- 媒体全部走 GitHub → jsDelivr CDN。
- 背景只保留 1 张活动图层，不重复 DOM 堆叠。
- 锁屏只预载当前页与相邻页。
- 大范围 `backdrop-filter` 禁止；只允许小型卡片局部使用并提供 fallback。
- `touch-action: pan-y` 与横向 swipe 手势不能破坏聊天纵向滚动。
- 所有真正可点击元素用 `<button>`，不得用纯 `<div onclick>` 冒充。
- 最小触控区域 44×44px。
- 图片加载失败时使用深墨+赤金渐变 fallback，UI 仍可操作。

## 12. 美化验收硬门槛

以下任一出现即判定视觉 QA FAIL:
- 白底/灰底后台表格感
- 五阵营直接做成浏览器默认进度条
- 锁屏图片被文字大面积遮脸
- 咩姬×多娜背景被完全盖住
- 名姬卡塞入人物简介或多余字段
- 按钮触控区小于 44px
- 页面在 360px 宽 Android 屏明显横向溢出
- 动画造成连续高耗电/掉帧

本文件优先级高于实现者个人审美。除非用户明确返工，不得自行改成另一套视觉语言。
