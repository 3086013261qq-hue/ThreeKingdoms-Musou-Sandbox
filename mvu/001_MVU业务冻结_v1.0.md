# 三国无双姬 MVU 业务冻结 v1.0

状态: FROZEN
适用: 咩咩全栈 v1.0.0 原生 MVU 九件套
原则: 不修改咩咩预设本体；不复制第二套角色好感；MVU 只补充三国无双姬自己的轻业务。

## 1. 总体结构

MVU 仅保留三层:
1. 五阵营锁屏画廊
2. Page 1「阵营亲和」
3. Page 2「名姬风华录」

禁止新增剧情页、地点页、角色详情页、背包页、状态页、百科页；这些职责由咩咩预设与世界书承担。

## 2. 锁屏

- 固定 5 页，顺序: 曹魏 → 蜀汉 → 孙吴 → 晋 → 群雄。
- 五张正式锁屏图均来自 `mvu/media/lockscreen/`。
- 支持左右手势滑动。
- 左右两侧必须有真正可点击的 `<button>`，Android 触控区域不得小于 44×44px。
- 底部只显示当前阵营名与 `n / 5` 页码，不堆业务信息。
- 中央主体区域点击进入 MVU。
- 禁止自动轮播，避免打断阅读；只记忆当前会话最后一页。
- 相邻页可预载，禁止一次性解码五张大图造成 Android 卡顿。

## 3. Page 1「阵营亲和」

固定 5 项:
- 曹魏
- 蜀汉
- 孙吴
- 晋
- 群雄

### 3.1 真值来源

阵营亲和唯一真值来自每轮 assistant 回复末尾唯一完整 `<faction_affinity>...</faction_affinity>`。

禁止把五阵营亲和值复制进 `stat_data` 或建立第二套持久化真值。
MVU/runtime 只读取聊天历史中最新一个合法完整块。

### 3.2 初值与范围

- 初值: 五阵营全部 0。
- 范围: -100 ～ +100。
- 无历史合法块时使用初值。
- 每轮必须精确继承上一合法块累计值，再结算本轮实际事件。
- 时间流逝本身不产生亲和变化。

### 3.3 增减刻度

沿用咩咩角色好感的成熟幅度语言，但事件必须具有阵营意义:

正向:
- +0: 普通交流、交易、私人寒暄；未形成阵营利益。
- +1: 公开示好、小型委托、少量情报或资源援助。
- +3: 实质帮助阵营军民、完成重要任务、保护一支部队或解决明显困境。
- +5: 救援核心人物、扭转重大危局、承担重大风险维护阵营核心利益。

负向:
- -1: 轻微公开冒犯、拒绝合作、小规模利益冲突。
- -5: 公开侮辱、主动妨碍阵营行动、明确与该阵营交战。
- -10: 重创重要人物/军队、重大欺骗、严重破坏战略利益。
- -50: 正式决裂级背叛、刺杀核心领袖、主动进入不死不休敌对状态。

### 3.4 阵营传播门槛

对单一武姬的私人行为默认只影响咩咩原生角色好感，不自动影响整个阵营。
只有当行为具有公开性、政治性、军事性、组织性，或实际影响阵营利益时，才结算阵营亲和。

「群雄」不是统一政权；它代表非魏蜀吴晋独立势力对玩家形成的总体名声。对单一地方诸侯的私交不应机械改动群雄值，除非影响广泛传播或具有代表性。

### 3.5 阶段显示

- -100～-80: 不死不休
- -79～-50: 敌视
- -49～-20: 对立
- -19～-1: 警戒
- 0～19: 中立
- 20～39: 友善
- 40～59: 认可
- 60～79: 信赖
- 80～99: 同盟
- 100: 生死与共

阶段只用于显示，不额外触发隐藏业务。

### 3.6 固定输出格式

每次正常 assistant 回复末尾必须且只能输出一个完整块。即使本轮五项变化均为 0，也不得省略。

```text
<faction_affinity>
曹魏亲和: 0/100 | 本回合: +0 | 原因: 无
蜀汉亲和: 0/100 | 本回合: +0 | 原因: 无
孙吴亲和: 0/100 | 本回合: +0 | 原因: 无
晋亲和: 0/100 | 本回合: +0 | 原因: 无
群雄亲和: 0/100 | 本回合: +0 | 原因: 无
</faction_affinity>
```

规则:
- 当前值允许负数，例如 `-23/100`。
- `本回合` 是 delta，不是累计值。
- `原因` 简短描述实际已发生事件；无变化写「无」。
- 禁止预测未来事件提前结算。
- 同一已结算事件不得跨楼重复收费。

## 4. Page 2「名姬风华录」

### 4.1 固定收藏池

- 固定对应世界书 89 名正式角色。
- 多娜、咩姬是彩蛋，不计入 89，不进入风华录收藏数。

### 4.2 点亮规则

- 某正式角色首次进入咩咩原生人物关系/好感记录，即视为「已邂逅」。
- 风华录只镜像咩咩现有关系数据，不为 89 人建立第二套好感变量。
- 已邂逅角色即使死亡、退场、关系恶化，名片仍保持点亮。
- 未邂逅角色不得提前显示姓名，统一显示 `???`。

### 4.3 名片显示

已点亮名片只允许显示:
- 角色姓名
- 咩咩原生角色好感度数值

禁止显示:
- 武道等级
- 武器
- 身高体型
- 人设摘要
- 阵营详情
- 角色正文
- 额外自建好感阶段

名片不需要点击展开详情。

### 4.4 筛选与进度

顶部允许轻量筛选:
`全部 | 曹魏 | 蜀汉 | 孙吴 | 晋 | 群雄`

显示 `已录 X / 89`。
筛选只影响视觉排列，不改变点亮状态。

## 5. 刷新与兼容

- 后续 AI 楼层必须实时刷新，不得停留在旧楼数据。
- assistant 消息兼容 SillyTavern / Tavern Helper 常见形状；不得只依赖 `role === 'assistant'`。
- 读取逻辑应优先接受 `is_user !== true` 且内容中存在合法标签的消息。
- `<faction_affinity>` 解析失败时保留上一合法值，不得清零。
- 风华录读取失败时只降级为未加载状态，不得写回覆盖咩咩数据。

## 6. 禁止事项

- 禁止第二套角色好感。
- 禁止用角色好感平均值计算阵营亲和。
- 禁止时间跳跃按天数刷阵营分。
- 禁止把风华录当百科。
- 禁止未来角色预解锁。
- 禁止改变 89 正式角色、世界书、时间线与咩咩预设业务。
