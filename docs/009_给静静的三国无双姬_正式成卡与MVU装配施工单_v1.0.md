## 四、MVU正式业务——只实现，不重新设计

MVU结构固定为：

1. 五阵营锁屏画廊；
2. Page 1「阵营亲和」；
3. Page 2「名姬风华录」。

禁止新增剧情页、地图页、背包页、人物详情页、百科页、状态页。

### 4.1 五阵营锁屏

固定顺序：
`曹魏 → 蜀汉 → 孙吴 → 晋 → 群雄`

必须：
- 使用 `mvu/media-manifest.v1.json` 内锁定 commit 的 jsDelivr URL；
- 左右 swipe；
- 左右真实 `<button>`；
- Android 真实触控区 >= 44×44px；
- 中央点击进入 MVU；
- 页码 `n / 5`；
- 不自动轮播；
- 只预载当前页与相邻页；
- 图片加载失败有深墨/赤金 fallback；
- 按钮点击不得穿透触发进入。

### 4.2 阵营亲和

唯一真值：聊天历史中最新一个合法完整 `<faction_affinity>...</faction_affinity>`。

五项固定：曹魏、蜀汉、孙吴、晋、群雄。

范围：`-100 ～ +100`，初值全部0。

AI每轮必须：
1. 继承上一合法块累计值；
2. 只结算本轮实际已经发生的阵营意义事件；
3. 使用冻结刻度 `+0/+1/+3/+5` 与 `-1/-5/-10/-50`；
4. 输出新的完整五项累计值；
5. 即使全0变化也输出唯一完整块；
6. 时间经过本身不刷分；
7. 单一武姬的私人互动默认只影响咩咩角色好感，不自动传播到阵营；
8. 禁止同一事件跨楼重复收费；
9. 禁止预测未来事件提前结算。

固定格式严格服从 `mvu/001_MVU业务冻结_v1.0.md`。

**禁止**把五阵营亲和值复制到 `stat_data` 或建立第二套持久化真值。

输出保险应使用咩咩全栈允许的卡级提示 / PHI 等原生机制实现，不修改咩咩预设本体，也不要为了实现标签去改写既有世界书正文。

### 4.3 最新楼层实时刷新

必须吸收《无职转生·因果法典》已验证过的兼容经验：

- 不得写死 `role === 'assistant'`；
- SillyTavern / Tavern Helper 消息形状可能无 role；
- 应优先接受 `is_user !== true` 且正文存在合法标签的消息；
- 每次新 AI 楼层后重新查找最新合法完整块；
- 新块解析失败时保留上一合法值，禁止回零；
- 不得长期停留在旧楼层状态。

### 4.4 名姬风华录

固定收藏池：89名正式人物。

数据源：咩咩原生人物关系 / 好感记录。

点亮：某正式人物首次进入咩咩原生关系记录即永久视为已邂逅。
死亡、退场、好感下降均不得重新熄灭。

未邂逅：
- `???`
- `未邂逅`

已邂逅：
- 只显示角色姓名；
- 只显示 `♥ 咩咩原生好感度`。

禁止：
- 第二套角色好感；
- 自建89个好感变量；
- 人物详情弹窗；
- 武器、武道、简介、身材、阵营说明等额外字段；
- 用阵营亲和反推角色好感；
- 用角色平均好感计算阵营亲和。

顶部允许：
`全部 | 曹魏 | 蜀汉 | 孙吴 | 晋 | 群雄`
以及 `已录 X / 89`。

- 白底 / 灰底后台表格感；
- Bootstrap / Material 默认组件感；
- 浏览器默认 progress bar；
- 大面积赛博霓虹；

- 360px Android 宽度横向溢出；
- 常驻粒子、持续大面积 blur、无限呼吸光；
- 点击控件使用 `<div onclick>` 冒充按钮。
